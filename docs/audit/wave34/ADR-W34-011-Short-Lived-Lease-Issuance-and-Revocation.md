# ADR-W34-011 — Short-lived writer leases, revocation and stale-writer recovery

**State: PROPOSED / NOT RATIFIED. Production NO-GO.**
**Verified starting point:** Wave34.8 draft PR #41, source SHA 68957fce394b170a820358fa2e50c98b28333b3d, successful workflow #42654714122. This is a synthetic PostgreSQL16 laboratory, not a secure production service.

## Problem and source-derived findings

Wave34.7's epoch claim was a spoofable PostgreSQL custom GUC. Wave34.8 replaced it with PostgreSQL-authenticated LOGIN principals and a database-owned epoch mapping, but an authorized old principal could retain permission indefinitely unless the privileged registry or epoch changed. A single database administrator remained able to bypass the controls. Neither milestone delivered an external issuer or leader quorum.

Wave34.9 introduces a *short-lived possession factor* to the disposable role-isolation model. A separate test LOGIN role inserts opaque random UUID leases bound to one PostgreSQL \`session_user\`, one epoch, and a database-server \`expires_at\`. A revocation timestamp makes a token ineligible before expiration. A SECURITY DEFINER trigger uses the current OPEN epoch and an exact matching lease row, with \`FOR SHARE\` locks on both fence and lease, before allowing a finance table write.

**Critical limitation:** This is a database-local bearer mechanism with tokens generated by a CI test fixture. It is not an independently operated issuer, cryptographic key service, non-exportable device identity, or production authorization. A stolen bearer may be replayed by the same principal before revocation/expiry, and the privileged CI PostgreSQL owner can bypass all guards.

## Roles and principal boundaries

| Principal | Narrow test grants | Denials |
| --- | --- | --- |
| Writer-1 | PostgreSQL LOGIN; INSERT ledger + limited payment plan update | Cannot read/issue/revoke leases, change fence, ALTER trigger, or impersonate operator/issuer |
| Writer-2 | Separate LOGIN; same limited finance DML | A lease for Writer-1 is rejected even if its bearer string is known |
| Lease issuer | Separate LOGIN; INSERT token grants and UPDATE only revoked_at | No finance DML, no epoch fence mutation, no SQL object ownership |
| Epoch operator | Separate LOGIN; SELECT/UPDATE fence row only | Cannot mint/revoke leases or post payments |
| CI owner | Creates roles, SQL fixture and SECURITY DEFINER function | Superuser, hence **not an acceptable production boundary** |

The lease token is held by the client and put into a transaction-local custom setting. The trigger treats it only as possession evidence and separately checks session_user, epoch, expiry and revoked_at. It does not regard the setting as an authenticated identity. Tokens never appear in evidence manifests.

## Wave34.9 exact synthetic acceptance

- **W349-01 — Issue/revoke:** no token -> SQLSTATE 55000; valid epoch-1 grant -> one synthetic ledger posting; unknown token and revoked token -> reject, no balance mutation. Only the test issuer role can revoke.
- **W349-02 — Expiry/permissions:** a one-second token expires using PostgreSQL clock time; a token for Writer-1 cannot be used by Writer-2. Restricted writer cannot UPDATE fence or lease, read the lease table, disable trigger, SET ROLE or SET SESSION AUTHORIZATION. Issuer cannot move the fence; operator cannot issue a lease or insert payments.
- **W349-03 — In-flight drain:** a writer's \`FOR SHARE\` lease/fence locks cause the operator's bounded freeze to time out with 55P03. After writer COMMIT, freeze succeeds. Old-epoch token and new-epoch token during FROZEN mode are denied. Reopening at epoch 2 enables only a Writer-2 token issued for epoch 2.

Each test uses a randomly generated \`w349_...\` schema, disposable PG16 database, four temporary LOGIN roles and credentials, synthetic account/ownership/payment records and no real provider endpoint. Teardown drops the schema and roles; no production migration or runtime changes.

## Proposed production issuer contract — NOT IMPLEMENTED

1. An independently administered issuer with non-overlapping epochs and trusted identity attestation. Define key custody, audience, writer principal, database tenant, issued-at, expiration, revocation, trace ID, nonce, fail-closed outage behavior and replay constraints.
2. Prove credentials/lease secrets cannot be exported or replayed by an already-compromised writer. Opaque bearer UUID alone does not satisfy this. Evaluate short-lived mTLS-bound identity, managed-workload tokens, and a database-enforced issuer signature, with verified algorithms and rotated/revoked keys.
3. Enforce storage-layer fencing across all financial writes and all old/new leaders under network partitions. A local PostgreSQL trigger is not a globally fenced primary. Separate the operator from the data-plane principal and use independently approved least-privilege DDL ownership.
4. Define the writer-drain snapshot boundary, WAL LSN/timeline and financially reconciled source/target manifests, failed revocation and transaction retry semantics, operator RPO/RTO, recovery and canary.
5. Resolve the legacy \`PAY-999999\` → \`PAY-1000000\` lexicographic ID collision, unkeyed public PaymentProcessor, production migration, money unit/currency, real provider PVA-01..16, refunds/chargebacks/outbox and independent owner+DBA+AppSec+payments+QA+SRE+legal review.

## Explicit exclusions and decision

No issuer key, real provider credential, customer data, live payment, persistent database, production SQL migration, application schema v6, runtime API, protected Git branch, release workflow or historical Stage27/Phase16 disposition is changed.

**Decision: PROPOSED, production NO-GO. Passing the CI role/lease tests is evidence only.**
